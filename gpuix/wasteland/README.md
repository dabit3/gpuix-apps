# WASTELAND: NEW YORK

A post-apocalyptic RPG with **zero asset files**, rendered by [GPUIX](https://github.com/remorses/gpuix) inside Ghostty over the Kitty Graphics protocol. Every pixel is generated by TypeScript at runtime: the isometric Manhattan map, buildings, characters, faces, weapons, the green-phosphor WRIST-LINK, the bitmap font, and the CRT curvature and scanlines.

Demo: [media/demo.mp4](media/demo.mp4)

## Run

```sh
cd gpuix/wasteland
bun install
bun link            # puts `wasteland` on PATH
wasteland           # title screen + character creation
```

Needs Ghostty or kitty (GPUIX terminal mode does not work in tmux or the VS Code/Zed terminals).

```
wasteland              title screen / character creation
wasteland -c           continue from ~/.wasteland/save.json
wasteland -n           skip creation, start a default character
wasteland log [-f]     print (or follow) the game log
wasteland save         summarise the save file
wasteland radio "msg"  broadcast on 101.1; a running game hears it
wasteland --help
```

Run it, split the pane (Cmd-D), and use the other pane: `wasteland log -f` follows the game log live, `wasteland radio "..."` shows up in the game's log and Radio tab, and `wasteland save` reads the save written by Ctrl-S. `WASTELAND_HOME` moves the data directory.

### Controls

| Input | Action |
| --- | --- |
| click map | walk / talk / loot / attack (hover shows names) |
| arrows / WASD | step |
| scroll | zoom the map |
| 1-5 or click tabs | WRIST-LINK: Status, Items, Map, Quests, Radio |
| 1-9 | dialogue choices |
| T | enter T.A.R.G.E.T. (combat); up/down picks a body part, left/right the enemy, Enter fires |
| E | end turn |
| Ctrl-S / Ctrl-L | save / load |
| Tab / I | cycle tabs (toggle the WRIST-LINK menu when the pane is narrow) / jump to Items |
| Ctrl-C | quit and restore the terminal |

## What's in it

- **Character creation**: 7 original attributes (Grit, Wits, Reflex, Charm, Stamina, Perception, Fortune), derived skills, pick 2 of 6 perks.
- **World**: Shelter 34 and a 40x32-tile Lower Manhattan district (brownstones, bodega, St. Brigid's church, the Bleecker St subway station, a collapsed overpass, radioactive crater), 13 named NPCs, 4 enemy types, 24 items.
- **Quests**: 2 main (Clean Water, The Overpass) and 4 side quests (Where's Rusty?, The Bell of St. Brigid, Bodega Run, Static on 88.1) with branching outcomes across two factions (Subway Union, Ironbacks).
- **Dialogue trees** with attribute/skill checks and faction reputation; portraits are procedurally generated faces.
- **Inventory** with weight, item condition, repair (kits, Tinkerer perk), barter with a trader, lootable containers, healing items, radiation (pools, Glowhounds, Rad-Flush), XP and level-ups.
- **T.A.R.G.E.T.**: combat pauses into turns; each body part shows a hit chance from skill, distance, cover, and lighting; shots spend AP, and the camera zooms toward the target with a slow tracer.
- **Saves** to `~/.wasteland/save.json` (that file is the "export"), a plain-text log at `~/.wasteland/log.txt`.

Content lives in JSON under `src/data/` (items, enemies, quests, NPCs and dialogue, and the map from `scripts/gen-map.py`).

## Zero assets

There is no image, audio, or font file in the app. `bun run check:assets` fails if any image or audio file (`.png/.jpg/.gif/.webp/.bmp/.ico/.svg/.tga/.ktx/.dds/.mp3/.ogg/.wav/.flac/.aac/.m4a/.opus`) exists outside `node_modules/` and `media/` (which only holds the demo video). UI chrome uses the system Menlo font; the rendered views use the in-code bitmap font.

- `src/render/iso.ts` builds the static isometric layer once: per-tile procedural materials (brick, concrete, asphalt, rust, rubble, grass) from value noise, building blocks with window patterns, fire escapes and damage.
- `src/render/frame.ts` composites the dynamic layer per frame (characters, shots, highlights, labels) into an RGBA buffer, then applies a curved-CRT lookup table, scanlines, and a phosphor palette. The buffer is pushed into an `<img>` with `setImagePixels`.
- `src/render/art2d.ts` draws portraits (face shape, eyes, nose, mouth, scars, hair), weapons assembled from barrel/receiver/stock/scope parts with wear, the district map, and the radio waveform.
- `src/render/font.ts` is a 5x7 bitmap font defined in code.

## Adapted from the original prompt

The prompt asked for a browser game (Vite + Three.js + Web Audio). This is a GPUIX app in the terminal instead:

- **Three.js/WebGL → CPU renderer into `<img>`.** A 2.5D isometric renderer written in TypeScript; the UI chrome (tabs, panels, dialogue, combat HUD) is native GPUIX elements.
- **Names.** WRIST-LINK and T.A.R.G.E.T. as the prompt requires; no Fallout/Pip-Boy/V.A.T.S. names or likenesses.
- **localStorage → files.** Saves, the log, and radio broadcasts are files in `~/.wasteland/`, so another pane (or any shell tool) can read or write them.
- **Radio.** Stations are listed in the Radio tab with a procedural waveform; `wasteland radio "..."` is a real cross-process broadcast into the running game.

### Cut

- **Audio.** GPUIX has no audio output, so the Web Audio SFX and generative radio music were cut. The Radio tab is visual only.
- **Real-time movement.** Exploration is tile-based (click-to-walk with pathfinding); combat is turn-based.
- **Scope.** One district without building interiors, and a shorter campaign than the prompt's 45-60 minutes (not timed).
- **`npm run build` static site.** Not applicable to a CLI; the asset check runs against the app folder instead.

## Tests

```sh
bun test            # engine playthrough, render, and GPUIX test-renderer UI tests
bun run typecheck
bun run check:assets
```

- `tests/engine.test.ts`: content counts, every dialogue edge resolves, every NPC/container reachable, both main quests completed via the peaceful ending with a save/load mid-quest, failed checks, loot, repair, healing, barter, radiation, T.A.R.G.E.T. combat.
- `tests/render.test.ts`: a varied, non-empty isometric frame within the time budget; portraits differ per NPC and weapons show wear.
- `tests/app.test.tsx` (`@gpuix/react/testing`): character creation, starting the game, tabs, inventory art, dialogue by keyboard, Ctrl-S save hook, narrow-pane layout.

## Performance

Measured on this macOS VM (Apple Paravirtual GPU, no real Mac GPU): the CPU renderer takes about 6 ms per 1000x700 frame after a ~70 ms first frame (`bun scripts/preview.ts`). The world view redraws at up to 60 Hz while something moves and idles otherwise. End-to-end terminal frame rate is bounded by the Kitty-protocol transfer and the paravirtual GPU, so expect a real Mac to be smoother than the recording.

## GPUIX findings (0.11.0, terminal mode)

- Every `<text>` needs an explicit `color`, and `<div>` is not flex unless `display: 'flex'`. `flex: 1` isn't a style key; use `flexGrow/flexShrink/flexBasis`.
- Keyboard needs a focused root (`<div tabIndex={-1} autoFocus onKeyDown>`). In terminal mode, letters can arrive as `key: "space"` with the character in `keyChar`; the handler checks both.
- The test renderer reports Ctrl as `modifiers.ctrl` while the native renderer can report `modifiers.control`; check both.
- The left mouse button is `0`.
- Positioned overlays need `pointerEvents: 'none'` or they swallow map clicks.
- `setImagePixels` with a reused RGBA buffer is fast enough for a full-pane game view in Ghostty.
- GPUIX prints `[gpuix] created native window / mount complete` with `console.log`, and terminal mode holds stdout until exit, so they appear under the restored prompt. The CLI filters `[gpuix]` lines; `RUST_LOG=error` (set by the bin shebang and a re-exec) silences the Rust INFO/WARN logs.
- Never pipe into the app's stdin: GPUIX treats a stdin pipe as its automation protocol. Cross-pane features go through files in `~/.wasteland/`.
- Ghostty owns Cmd shortcuts, so all in-game shortcuts are plain keys or Ctrl.
